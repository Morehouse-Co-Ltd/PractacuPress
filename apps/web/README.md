# Practacu Press 前端

React 19 + Vite + TypeScript 单页应用，严格按
[`packages/contracts/openapi/openapi.yaml`](../../packages/contracts/openapi/openapi.yaml)（v0.1.0）
和设计文档第 7、11 章实现。包含**站点前台**、**管理后台**和**首次打开安装引导**。

内置 **2 套大主题**（原版：纸白单栏 / 夜航：暖黑暗色双栏）与 **7 套配色预设**
（纸白、暖砂、雾蓝、灰绿、陶土、夜航、夜航·浅色），以及
**无代码页面编排**（区块组件库 + 首页 / 页面编排 + 思维链逻辑 + 页面模板），全部零新增依赖。

> 设计稿原计划由外部团队实现前端；此目录是按该契约落地的前端，仅依赖公开 REST 接口。

## 运行

```powershell
cd apps/web
npm install
npm run build     # 首次运行先构建
npm start         # 默认 80 端口
```

打开 `http://localhost`（80 是浏览器默认端口，地址栏不用写端口号）。
`npm start` 运行 `scripts/serve.mjs`：提供 `dist/` 的静态托管与 SPA 回退。

**端口可以在后台修改**：「站点设置 → 访问端口」里填新端口并应用，服务会立即在新端口监听，
本页自动跳转，选择会写进 `apps/web/.runtime/web.json`，下次启动沿用。切换时当前地址的
安装配置、演示数据与自定义页面会通过一次性令牌迁移到新地址，不需要重新安装。
也可以在启动时指定：

```powershell
npm start -- --port 8080          # http://localhost:8080
$env:PP_WEB_PORT=8080; npm start  # 等价写法
$env:PP_WEB_HOST=0.0.0.0; npm start  # 允许局域网访问（默认仅本机）
```

开发模式：

```powershell
npm run dev                 # 默认 http://localhost（80）
npm run dev -- --port 5173  # 80 被占用时换一个端口
```

开发服务器会把 `/api`、`/healthz`、`/readyz` 代理到 `http://127.0.0.1:8080`（Go API）。
它的端口在启动时确定，后台的端口面板会给出重启命令，不会假装能热切换。
80 被占用时 Vite 会自动顺延到下一个空闲端口，并以终端输出为准。

要求 Node 22+。生产部署时也可以用 Nginx 托管 `dist/`，把 `/api` 与健康检查转发到 Go API；
这时端口由反向代理决定，后台面板会提示当前不是内置静态服务。

### Windows 一键启动包（一键打包）

```powershell
# 在仓库根目录双击 打包.bat，或者：
powershell -ExecutionPolicy Bypass -File scripts\package.ps1
```

脚本会自动构建前端、编译 Rust 安全服务、把 `dist` 内嵌进启动器、编译 Go 启动器与 API，
然后在临时端口启动产物做自检（静态站、`/__pp/runtime`、注册、文章创建与 Rust 清洗、发布），
最后生成 `release/PractacuPress-Windows-x64.zip` 并同步 `release/PractacuPress`。
解压后双击 `PractacuPress.exe` 即启动，不需要安装 Node。启动器（`apps/launcher`）把 `dist`
内嵌进 exe，并实现与 `scripts/serve.mjs` 相同的 `/__pp/runtime` 运行时接口，
所以后台改端口、数据迁移都能照常用。

没有 Rust 工具链时可以加 `-SkipSecurity` 打一个不带安全服务的包（发布与上传会返回 503）。
压缩包只包含程序与 `README.txt`，不会把开发机的 `data/` 带进去。

包里同时带有 `PractacuPressAPI.exe`（Go API）。启动器默认会把它拉起来，在同一端口上
反向代理 `/api`、`/healthz`、`/readyz`，因此安装引导里的「真实环境」不需要填地址，
也没有跨域问题。API 使用 exe 同目录 `data/practacu.db`（纯 Go SQLite），首次启动自动
建表、建默认站点，引导里创建的第一个账户即平台管理员。`/__pp/runtime` 会附带
`runtime_mode` 与 `api` 状态，引导据此判断本机后端是否由启动器托管。
`PractacuPress.exe --mode demo` 可以强制只用静态前端。

### 真实环境：零输入自动连接

选择「真实环境」后不需要填写 API 地址。引导会按顺序探测：

1. 同源接口（`/healthz`、`/readyz`），适合反代同域部署、`npm run dev`（Vite 已代理到 8080）
   与 Windows 一键包（启动器已把本机 API 代理到同源）；
2. `http://127.0.0.1:8080` 与 `http://localhost:8080`，适合手动启动的本地开发。

探测同时校验 `/healthz` 与 `/readyz` 的 JSON 形状，SPA 的 HTML 回退不会被误判为健康。
连上后会跳过数据库步骤（数据库由服务端配置），直接进入管理员账户。

- 启动器托管 API 时，选项会直接标明「本机 API 已就绪」，失败提示会区分
  「API 没起来」与「启动器没带 API」，不再展示 `go run` 命令。
- 启动后端后点「重试」即可，不需要再输入地址。
- 后端不在同源、也不在本机 8080 时，才需要展开「手动指定地址」。
- 完全没有后端时，可以一键「先以演示数据继续」，不会卡在安装里。
- 已启动但仍失败，通常是跨域：开发用 `npm run dev`，生产把前端与 API 放在同一域名下。

真实环境的「访问域名」可以留空：生产环境此时只允许公网 IP 直接访问（本机开发与桌面启动器
仍可用 localhost）。在「站点设置 → 访问与域名」里设置主域名会同时写入已验证时间，并可一起
配置 Let's Encrypt 或手动 SSL 证书、别名与 HTTPS 跳转；只保存部署意图，证书与 Nginx 片段仍需
部署到服务器。

两个重要的事实边界：

- 浏览器**不能**修改服务端进程的环境变量。演示模式的数据库步骤只生成可粘贴的 `DATABASE_DRIVER` /
  `DATABASE_DSN` 片段，实际连接以服务端为准；真实环境不再询问这些值。
- OpenAPI 没有“创建站点”端点。连接真实后端时，引导会注册管理员、读取 `/me` 与默认站点，
  再用 `PATCH /sites/{id}/settings` 写入站点规则。

完成后写入本地安装配置（`pp.web.config.v1`），刷新页面即可直接进入站点。

### 本地配置与服务端核对

安装状态存在两处：服务端的 `data/` 目录，和浏览器的 `localStorage`。删掉 `data/`、
换一份数据目录、或者数据库被重建时，服务端已经是全新站点，但浏览器仍然记着「装好了」——
页面会直接渲染一个空站点，安装引导再也进不去。

所以真实环境启动时会向 `GET /api/v1/setup/status` 核对一次：

| 服务端答复 | 处理 |
| --- | --- |
| `installed: true`，`site_id` 与本地一致 | 照常进入站点 |
| `installed: true`，`site_id` 不同 | 判定为过期安装：清配置、整页跳到 `/?mode=live` |
| `installed: false`，`reason: no_site` | 同上 |
| `reason: domain_unverified` | 保留配置（重装解决不了未验证域名） |
| 网络失败 / 非 2xx / 老版本 API 没有这个端点 | 保留配置，下次启动再试 |

只有拿到明确答复才清配置：断网一次就让人重装，代价远高于多渲染一次空站点。
`has_admin` 只用于排查，不参与判定——服务端部署的首个账户本来就是普通成员，拿它触发
重置会让向导反复重来。被重置时安装引导顶部会说明原因。

这个端点挂在 `/api/v1` 分组**之外**：分组会先解析站点，没有站点就直接 404，而
「没有站点」恰恰是这里要给出的答案。


### 站点形态：个人博客与社区站点

默认站点步骤可以选择站点形态，安装完成后也能在「站点设置 → 站点形态」切换：

| | 个人博客 | 社区站点 |
| --- | --- | --- |
| 账户 | 自助注册关闭；站长在「成员与角色」里创建账户 | 访客可以自助注册 |
| 后台权限 | 所有账户都能登录后台，统一按最高管理员处理 | 按成员 / 审核员 / 管理员 / 最高管理员分组 |
| 前台入口 | 页头只保留「管理员登录」 | 显示「登录 / 开始使用」 |
| 登录 | 任意已创建账户；注册页给出“请联系站长创建” | 任意成员账户 |
| 评论 | 按站点评论设置；默认开启，可先审后发 | 同左 |
| 私信 | 入口隐藏（没有其他成员可以发起会话） | 可用 |
| 阅读与发布 | 固定公开阅读、直接发布 | 按访客模式与发布模式 |
| 数据 | 切换形态不会删除账户、文章、评论或媒体 | 同左 |

站点形态保存在本地安装配置里（`site_kind`、`owner_email`、`role_snapshot`）。切到个人博客时，
前端会把非平台管理员账户提升为站点管理员，并把原角色记进 `role_snapshot`；切回社区站点时按快照恢复。
v0.1.0 的 `Site` 没有注册开关，因此**个人博客的注册关闭是前端策略**：真实后端仍需在网关或服务端禁止
`POST /api/v1/auth/register/email`，否则直接调用 API 依然可以创建账户。README 与后台「接口与契约」页都标注了这一点。

### 登录方式：手机验证码与第三方登录

安装引导第 6 步和「站点设置 → 登录方式」都可以直接配置邮箱之外的登录方式：

| 方式 | 需要填写的非机密参数 | 服务端密钥 |
| --- | --- | --- |
| 手机验证码 | 短信服务商、短信签名、模板编号 | `SMS_ACCESS_KEY_ID`、`SMS_ACCESS_SECRET` |
| Google | Client ID、回调地址、Scope | `GOOGLE_CLIENT_SECRET` |
| GitHub | Client ID、回调地址、Scope | `GITHUB_CLIENT_SECRET` |
| 微信 | AppID、回调地址、Scope、账号类型 | `WECHAT_APP_SECRET` |

- 开关与参数写入本地安装配置的 `auth` 字段；填入完整必填项后，`/login` 才会显示对应入口。
- 密钥输入框只用于生成 `.env` 片段，**不会写入 localStorage**；页面会明确提示这一点。
- 演示模式下可以走完整流程：手机验证码固定为 `246810`，OAuth 点击「模拟授权并继续」会以站点管理员身份进入。
- 契约 v0.1.0 没有短信或 OAuth 端点。连接真实后端时，需要服务端实现页面上列出的端点；
  在此之前，真实模式只会显示端点说明与配置复制，不会伪造登录成功。

### 外观、页面与扩展（本地 CMS 层）

这三项是纯前端能力，配置存在 `pp.web.config.v1` 的 `customization` 字段：

| 能力 | 位置 | 说明 |
| --- | --- | --- |
| 外观 | 后台 → 外观 | 首页首屏（眉题 / 标题 / 副标题，单栏与双栏都读取）、品牌副标题、公告条、自定义 CSS；面板随当前主题声明的分区显示或隐藏 |
| 导航与页脚 | 后台 → 主题设置 → 导航与页脚 | 顶部 Tab（自定义文字 + 页面/外链，可排序，留空链接作分组；可设内置图标与左/右位置；可挂最多 8 个二级入口，渲染为页头下方胶囊栏或下拉菜单）；软件 / 社交快捷链接（GitHub、X、Mastodon、RSS、邮箱、网站，夜航显示在页头左上角，所有主题显示在页脚底栏上方）；页脚品牌区（标题 / 副标题 / 简介 / 状态标签文字）；页脚栏目（标题 + 文字/链接，最多 4 栏 8 条）；版权文案与底部右侧说明。全部内容都可自定义，留空回退站点信息或隐藏 |
| 页面编排 | 后台 → 页面编排 | 无代码搭建：三栏实时预览、拖拽、无限嵌套分栏、文本 CSS、图片/视频/网站/幻灯片、思维链逻辑、页面模板（详见下节） |
| 页面 | 后台 → 页面 | 页面内容全部由「页面编排」的区块组成（旧版 Markdown 正文会自动迁移成文本区块）；发布 / 草稿；加入页头导航（最多 3 个）；前台路径 `/:slug`；模板含关于页 / 友链墙 / 大事记 / 留言箱 / 空白页 |
| 扩展 | 后台 → 扩展 | 「内置扩展」6 个开关；「我的扩展」导入 / 启用 / 编辑 / 导出创作者扩展；「扩展工坊」写清单与 HTML/CSS/JS 并实时沙箱预览（详见下节） |

- 改动即时生效。主题通过 CSS 变量（`--bg`、`--ink`、`--accent` 与派生色）覆盖全站；
  派生色使用 `color-mix()`，需要 Chrome 111+ / Safari 16.2+ / Firefox 113+。
- 每套预设含浅色 / 深色两套令牌。页头切换明暗（月亮 / 太阳按钮），写入 `<html data-mode>`
  与 `color-scheme`，首屏由 `main.tsx` 预注入，刷新不闪色。
- **后台固定浅色**：`data-surface="admin"` 使用纸白令牌，前台暗色主题不会把后台表格、表单和卡片染灰。
- 「主题设置」顶部提供两套内置大主题：**原版**（纸白浅色 + 经典单栏）与 **夜航**（暖黑暗色 + 双栏卡片）；
  切换会同时更新配色、排版和单栏/双栏版式。只有首页仍为默认编排时才同步默认组件，自定义过的首页保留。
- 主题支持导入 / 导出 / 另存为 / 删除自定义主题；顶部是主题库，下面才是当前主题微调与高级令牌。
  页面编排、外观、导航与页脚、加载动画归入「主题设置」导航组；「外观」只保留主题允许的分区
  （首屏 / 品牌 / 公告 / 自定义 CSS），页脚整块搬到「主题设置 → 导航与页脚」。
- 「创建主题」可以从零建一套自定义主题：选单栏 / 双栏、配色起点与要绑定的外观分区，
  创建后直接进页面编排；自定义主题的外观分区（`SiteTheme.appearance`）随主题导出 / 导入，
  取消勾选的分区会从「外观」页消失，数据仍然保留。
- 自定义 CSS 只在站点前台挂载，不进入管理后台；不执行任何脚本。
- 页面路径会避开 `admin`、`articles`、`login` 等系统路由；草稿只有站点管理员能直接预览。
- 外观与页面可以用「外观 → 导出 JSON / 导入」在浏览器之间迁移；导出内容不含账户、文章与图片。
- 契约没有主题、页面或插件端点，所以这些内容不会同步到其他设备。接入后端后应改为服务端存储，
  或继续用导入 / 导出迁移。
- 内置扩展只运行随前端发布的实现；创作者扩展跑在 `sandbox="allow-scripts"`（没有 `allow-same-origin`）
  的独立 iframe 里，配 CSP `default-src 'none'`，拿不到主站 DOM、Cookie 与登录态，也不能加载远程脚本。

### 文章封面、Markdown 输入与链接卡片

| 能力 | 位置 | 说明 |
| --- | --- | --- |
| 自定义封面 | 后台 → 创作页右侧「封面」；内容库「封面」列 | 按内容 id 覆盖程序化封面：图片地址 / 上传（演示模式存 data URL，建议 600 KB 内）/ 焦点位置（居中、顶部、底部）/ 隐藏封面。列表卡片、首页各区块与文章详情统一生效 |
| Markdown 输入 | 后台 → 创作页正文 | 所见即所得编辑器里直接敲 Markdown：段首 `# ` `## ` `- ` `1. ` `> ` `[ ] ` `---`、行内 `**粗体**` `*斜体*` `` `代码` `` `~~删除~~` `[文字](https://…)` 会即时转成排版；粘贴 Markdown 会转成富文本。不新增源码面板 |
| 斜杠指令 | 后台 → 创作页正文 | 空段落输入 `/` 弹出插入面板：标题 / 列表 / 引用 / 代码块 / 分割线 / 提示框 / 图片 / 视频 / 表格 / 分栏 / 公式 / 链接，↑↓ 选择、Enter 插入、Esc 关闭 |
| 链接两种形态 | 工具栏「链接」/ `/` 面板 | **文字链接**：行内 `<a>`；**卡片链接**：封面 + 标题 + 域名说明的卡片，存入 Markdown 时保留为 HTML 区块（`a.pp-linkcard`），服务端清洗白名单不需要新增标签 |

- 封面存在 `customization.covers`，链接卡片与正文一起存在 Markdown 源文里，都不涉及新接口。
- 标题映射：正文标题从二级开始（一级留给页面标题），因此 `# ` → 二级标题、`## ` → 三级标题、
  `### ` / `#### ` → 四级标题，与工具栏的「标题 2/3/4」一致。
- 卡片链接只用白名单标签（`a` / `img` / `strong` / `em` / `br`），公开页渲染结果与编辑器预览一致；
  旧的「嵌入卡片」按钮保留，类名 `pp-embed` 向后兼容。
- 编辑器里的 Markdown 转换对中文 IME 做了保护：组词过程中不转换，组词结束后再补一次。

### 创作者扩展（沙箱）

入口：后台 → 扩展 → **扩展工坊**。扩展是一份 JSON 清单（`.ppext.json`）：

| 字段 | 说明 |
| --- | --- |
| `name` / `version` / `author` / `description` / `icon` | 展示信息 |
| `slots` | 挂载位置：站点页头 / 页脚、首页顶部 / 底部、文章顶部 / 底部 / 侧栏、悬浮窗 |
| `pages` | 适用页面：全部 / 首页 / 文章页 / 列表页 / 搜索页 |
| `permissions` | 申请的能力：通知、打开链接、站内跳转、剪贴板、主题信息、本地存储 |
| `html` / `css` / `js` | 沙箱正文、样式与脚本（上限 80K / 40K / 80K） |

- 工坊提供 3 个可直接运行的示例模板（文末作者卡、悬浮阅读计时、文章顶部提示条），也可以自己写。
- 「我的扩展」支持导入（选文件或粘贴 JSON）、启用 / 停用、编辑、复制、删除、单个导出与全部导出；
  导出文件可以再导入到别的站点。最多 20 个扩展，重复 id 会提示覆盖。
- 沙箱内可用受限 API：`PP.getContext()`（主题 / 页面类型 / 标题）、`PP.notify()`、`PP.open()`、
  `PP.navigate()`、`PP.copy()`、`PP.setHeight()`、`PP.storage.get/set()`。每项能力都要先在清单里声明，
  未声明的一律被宿主忽略；扩展高度会随内容自动调整。
- 安全边界：iframe 是不透明源，无法访问主站 DOM、Cookie、localStorage；CSP 默认禁止网络请求
  （只放行 https 图片与 data 字体）。扩展只能拿到宿主通过 `postMessage` 明确交还的能力。
- 扩展与主题、页面一样存在本地安装配置，不伪造服务端插件市场；换设备用 JSON 导出 / 导入迁移。

### 页头样式（吸顶 / 顶部透明 / 悬浮胶囊）

入口：后台 → 主题设置 → 导航与页脚 → **页头样式**。三套样式共用同一批导航 / 页脚配置，明暗主题通用：

| 样式 | 页面顶部 | 向下滚动后 |
| --- | --- | --- |
| 经典吸顶（默认） | 整条页头吸顶，半透明 + 模糊 | 加一层投影，强调已离开页首 |
| 顶部透明 | 页头完全透明，融进首屏 | 出现底色与投影，浮动在内容之上 |
| 悬浮胶囊 | 页头透明，内容与页面同宽 | 收缩成一条居中的圆角悬浮栏（宽度上限 1280px，窄屏铺满），类似参考站点 |

- **背景高斯模糊**可单独开关；开启后半透明背景 + `backdrop-filter`，强度 4–24px 可调；关闭则使用实色背景。
  悬浮胶囊只在滚动后才出现模糊层，页首保持完全透明。
- **滚动触发距离** 0–240px 可调（默认 8px）；切换使用 `is-scrolled` 类 + `scrollY` 判断，
  不会在滚动时改变页头高度，避免整页跳动。
- 样式变量挂在 `<html data-header-style>` 与页头的 `data-blur` 上，CSS 在
  `src/styles/header.css`（通过 `styles.css` 的 @import 引入）。所有颜色走主题令牌，夜航深色、
  明暗实时切换、后台固定纸白都不受影响；悬浮胶囊里的移动端菜单也会变成同款圆角卡片。
- 设置随「外观 → 导出配置」迁移；默认值偏保守（经典吸顶 + 10px 模糊），老站点升级后观感基本不变。

### 全屏页面编排（`/admin/theme`）

入口在后台导航「主题设置 → 页面编排」，按 `React.lazy` 单独分包，不拖慢首屏。

**工作台**

- 独立全屏工作台，中间是真实前台 iframe，铺满视口；
- 左侧「组件与结构」、右侧「区块属性」都是可收起的悬浮窗；标题栏可拖动，松手时靠近左右边缘会自动吸附，
  双击标题栏复位，位置记在 localStorage；拖动中用 requestAnimationFrame 合并移动、关闭背景模糊，更跟手。
- 顶部浮动工具栏：返回后台、编辑页面、撤销 / 重做、默认编排、外观入口；
- 底部浮动预览工具栏：桌面 / 平板 / 手机、**不同设备分割**开关（开启后三台设备各有一份独立编排）、刷新、新窗口；
- 后台导航和顶栏在编排时隐藏，返回后恢复；
- 本轮暂时移除顶部「页面编排 / 思维链 / 页面模板」切换标签；逻辑链改到右侧悬浮窗的「逻辑链」按钮里，用弹窗编辑。
- 左侧结构树用可展开/收起的父级、子级层级显示嵌套；父级显示子组件数量。
- 布局变体由「外观」里的内置主题决定，编排器顶部不再放经典/夜航切换。

**按设备独立编排**

- 底部快捷栏打开「不同设备分割」后，桌面 / 平板 / 手机各保存一份独立的区块编排；
  切换设备就是切换当前正在编辑的那一份，结构树、撤销/重做、预览 iframe 一起切换。
- 关闭开关时回到共用编排，以桌面版为准；再次打开会以当前共用编排初始化三台设备。
- 前台按窗口宽度自动选择：≥1024px 桌面、641–1023px 平板、≤640px 手机；
  某台设备没有独立编排时回退到桌面版，再回退到共用版。
- 数据仍保存在 `ScreenLayout` 里：`blocks` 是共用编排，`device_split` 与 `devices`
  保存分设备版本，随首页 / 页面配置一起导出导入，旧配置无需迁移。

**拖拽、缩放与嵌套**

- 组件库分「布局 / 媒体 / 数据与代码 / 内容」，点击追加，或直接拖入真实页面；
- 拖到 iframe 内时，预览桥会在鼠标下的真实区块上显示插入到上方 / 下方的指示线；
- 支持拖拽排序、跨列移动、拖入分栏容器；
- **无限嵌套**：分栏容器可继续放分栏容器，深度上限 8 层、整树 200 个区块；
- 新增「容器组」，把任意区块纵向组合成一个可整体移动的组件；
- 选中组件后可以直接拖预览里的缩放手柄改变宽度/最小高度，右侧也有数值输入；
- 每个组件都有「组件 CSS」，只写声明即可，作用域限于当前组件，可复制复用；
- 左侧点击区块会滚动中间预览到对应位置并高亮；
- 每个区块有独立入场动画，属性面板里可以点「预览动画」；切换动画选项也会自动重播。

**文本与富文本**

- 文本块支持眉题、标题、正文、对齐、最大宽度和块级作用域 CSS；
- 正文可打开富文本弹窗，复用文章编辑器：标题、粗体、列表、链接、图片、表格、分栏和公式；
- 富文本按 Markdown 保存，前台继续走现有 Markdown 渲染与清洗，不直接注入任意 HTML。

**新增区块**

- **分栏容器**：2 / 3 / 4 栏，子区块按列号分布，可继续嵌套；
- **容器组**：纵向嵌套任意组件；
- **文本**：上述富文本与作用域 CSS；
- **图片 / 视频**：地址、封面、说明、比例、链接；视频可开关原生播放条，并保留自定义播放/暂停按钮；
- **网站**：网站卡片或 sandbox iframe 嵌入；
- **幻灯片**：手动图片、标题、说明、链接，自动轮播、箭头、圆点和悬停暂停；
- **统计卡片 / 图表**：手填数据；图表可切换「本机访问统计」，支持柱状 / 折线 / 环形；
- **列表**：简洁 / 编号 / 图标三种样式；
- **文章组件**：最新或热门，单行列表 / 分栏卡片 / 悬浮卡片三种布局，条数、摘要、日期、标签、栏数可配；
- **分类胶囊**：手动写显示文字并绑定分类 slug，或切「自动读取分类」一行展示全部分类；
- **置顶文章 / 热门文章**（两个预设，同一个封面网格）：置顶读「内容库 → 首页精选」的名单，
  每篇占几格（1×1 / 2×1 / 1×2 / 2×2）在内容库里直接选；热门按 30 天阅读量排序，
  名次决定占格（2×2 → 2×1 → 2×1 → 四个 1×1，七篇一循环），排名一变排布就跟着变。
  两种都有可改的小节标题，格子越大显示的信息越多（标题 → 阅读量 → 摘要）；
- **自定义代码**：HTML + CSS + JS 在 `sandbox="allow-scripts"` 的独立 iframe 中运行，
  不能读取后台 Cookie 或操作主页面；适合写独立小组件，而不是修改站点全局功能。

旧配置没有 `children` 时继续按原平铺方式渲染；编排结果仍写入 `customization.home`
与 `customization.pages[].layout`，可随「外观 → 导出配置」迁移。

**性能纪律**：入场动画只用 `transform` / `opacity`，IntersectionObserver 只观察一次，
`prefers-reduced-motion` 下全部降级；区块渲染走注册表数据驱动，不引入运行时框架。

## 请求与安全

- **Access Token 只在内存**：`Session.access_token` 不写入 `localStorage` / `sessionStorage`。
  刷新页面后用 HttpOnly `pp_refresh` Cookie 重新换取。
- **刷新带 CSRF 双提交**：刷新请求读取可读的 `pp_csrf` Cookie 并回填 `X-CSRF-Token`；
  401 只会自动重试一次，失败即清空会话并回到登录页。
- **错误只按 `code` 分支**：统一解析 `application/problem+json`，展示 `message` 与
  `request_id`，不依赖文案。
- **写请求带 `Idempotency-Key`**：创建草稿、评论、消息与流程动作均生成一次性键。
- **统一 `X-Request-ID`**，列表使用 `items / next_cursor / has_more`。
- **只渲染服务端的 `rendered_html`**：`dangerouslySetInnerHTML` 仅用于该字段；编辑器里的本地预览
  先转义再拼装，不替代服务端清洗。
- **实时事件采用文档 7.7 的轮询降级**：45 秒刷新未读通知，窗口重新获得焦点时也刷新；
  WebSocket 票据端点已存在于契约，本版未启用长连接。
- 上传走两步：`POST /media/uploads` → multipart 字节 → `POST .../complete`；只有
  `scan_status=clean` 的资源会出现在列表中。

## 契约缺口与处理

v0.1.0 契约不完整的地方，前端不伪造接口，也不假装功能存在：

| 缺口 | 处理方式 |
| --- | --- |
| 列表不返回作者信息 | 作者归档用 `GET /users/{id}` 取公开资料、`GET /articles?author_id=` 与 `/posts?author_id=` 取内容；列表本身仍不显示作者名 |
| 编辑草稿需要 `source_body`，但接口只返回 `rendered_html` | 真实后端下关闭已有稿件的编辑入口，避免空白覆盖；新建草稿不受影响 |
| 没有创建站点端点 | 引导注册管理员后读取默认站点，再 PATCH 设置 |
| 没有媒体列表端点 | 媒体库只显示本次会话上传的文件 |
| 没有审计查询端点 | 操作日志记录在浏览器，并明确标注“不能替代合规审计” |
| 没有 `/moderation` / `/reports` 路由 | 不提供举报、封禁等无法兑现的入口 |
| `Site` 没有站点形态、评论策略或权限组字段 | 存在本地配置；切到个人博客时前端把成员提升为站点管理员并记录原角色，切回时恢复；评论开关与先审后发同样保存在本地 |
| 没有主题、页面或插件端点 | 存在本地 `customization` 配置（含主题预设、区块编排、思维链、权限组），支持 JSON 导入 / 导出；不伪造服务端同步 |
| 没有短信 / OAuth 端点 | `auth` 配置只记录开关与非机密参数，并生成服务端 `.env`；演示模式模拟入口，真实登录等待服务端实现 |

评论列表（`GET /comments`）与管理员创建账户（`POST /sites/{siteID}/members`）已补齐到
`packages/contracts/openapi/openapi.yaml` 与 `apps/api`；评论审核复用 `PATCH /comments/{id}`
的 `status` 字段。

接口补齐后只需替换 `src/lib/api.ts` 与 `src/lib/backend.tsx` 中的实现，页面无需改写。

### 深色模式适配与对比度审计

- 站点前台的组件一律使用主题令牌（`--bg` / `--bg-subtle` / `--ink` / `--muted` / `--line`），
  不再写死浅色背景：用户菜单、移动菜单、搜索浮层、命令面板、弹窗、表单控件、评论输入框、
  私信气泡与输入区、通知未读底色、空状态图标、骨架屏、分区色标签等都会跟着明暗切换。
- 后台固定纸白（`data-surface="admin"` 重新声明纸白令牌），前台切到深色也不会让表格、表单发灰。
- 分类色是数据里的深色值（深绿、藏蓝等），深色模式下会与文本色混合提亮，
  相关组件把颜色存进 `--pp-cat-color`，由样式表按 `data-mode` 决定最终颜色。
- 明暗切换是实时的：令牌挂在 `:root`，不需要刷新页面。
- 新增 `scripts/audit-contrast.mjs`（零依赖，CDP 驱动无头 Chrome）：逐页计算「文字色 vs 实际背景色」，
  对比度低于 3.2 记一条，输出 JSON 与截图。先 `npm run build` 并让 `scripts/serve.mjs` 在 80 端口
  提供服务（或对 `npm run dev` 的 5173 跑），然后：

  ```powershell
  cd apps/web
  $env:PP_AUDIT_THEME = 'paper-dark'   # night-dark / paper-light 也可以
  node scripts/audit-contrast.mjs
  # 报告：.tmp/dark-audit-<theme>.json；截图：.tmp/shots-dark-<theme>/
  ```

  当前结果：`paper-dark` 与 `night-dark` 下**站点前台 0 条**；剩余条目全部在后台固定纸白的
  `--faint` 提示文字上（浅色模式同样存在，属既有设计口径，不在明暗适配范围内）。
  带渐变背景的区块无法用纯色算法判断，脚本会跳过，改由截图人工复核。

```powershell
cd apps/web

```
